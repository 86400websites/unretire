## Sprint intent

- Goal and exit condition: a webinar funnel built as a template. /conversation carries two forms that upsert a
  Mailchimp contact and apply a server-fixed tag; the owner's two Mailchimp flows send the instant emails; a
  script in GitHub Actions creates the tags, three saved segments and seven empty drafts and proves the
  segment logic; the Stripe webhook tags buyers `purchased-course`. The date, time, Zoom link, replay link,
  offer deadline and code are Vercel env values; wording and the title are code. With WEBINAR_STARTS_AT unset
  the whole funnel is dormant (404), which is the Production state at merge. A set-but-malformed WEBINAR_*

## Hunt list

1. Correctness: exit criteria work in realistic success, empty, loading, and failure states that apply.
2. Authorization: gated routes/data paths, if any, authorize server-side before protected reads; admin paths
   verify role.
3. Secrets/env: no live env values, credentials, tokens, private keys, or server-only values exposed. A
   placeholder-only example file is acceptable only when it contains names/placeholders, not live values.
4. Data safety: no unintended anonymous path or silent data loss; database changes, if any, match the selected
   migration, rollback, and access-policy rules.
5. Input safety: untrusted values are validated before redirects, URLs, raw HTML, queries, or other sinks.
6. Build/deploy: imports, generated artifacts, routing/rendering mode, config, lockfiles, and hosting behavior
   have no unintended change.
7. Scope/content: actual paths match the sprint; approved copy/design/facts were not silently changed.
8. Regressions: the change does not weaken an existing guard or break a neighboring workflow.

Sprint-specific, in addition. The security pass matters here because this range opens the first public route
to a live mailing audience since launch, the first off-site redirect in a route handler, and the first CI path
holding the Mailchimp key.

9. **A registration is never reported as emailable unless the tag was applied.** `src/app/api/conversation/route.ts`
   and `src/lib/mailchimp/client.ts`: walk upsert failure, tag failure, timeout and thrown fetch. Each must end
   in an error response, never `ok`. The only `ok` without a tag is an upsert Mailchimp refuses as a forgotten
   or compliance-state address; a merge-field or generic 400 must be a 502, and a filled honeypot must be a
   400, never a fake success. Confirm an archived member is the only status that is ever set back to
   subscribed, and that an unsubscribed or cleaned member never is.
10. **Abuse control runs first and fails closed.** `checkRateLimit` is called before parsing and before any
   upstream call for every non-dormant request (a dormant route answers 404 before it), with its own bucket
   name; a limiter failure answers 429, not success. A missing Mailchimp key answers 503, never success. Confirm the abuse spec
   asserts both halves and that no payload in it could reach Mailchimp.
11. **The client cannot choose a tag.** The tag comes only from the server-side `form` switch. Confirm
   `/api/subscribe` now refuses `conv1-registered`, `conv1-toolkit` and `purchased-course`, and that the
   change did not alter any other accepted or refused case.
12. **No upstream text, URL, key or audience id reaches a response or a log.** Every `console.*` and every
   response body in the new route, the client helper, the webhook addition and the script. A thrown fetch
   error's message can carry the request URL.
13. **The redirect target is validated by parsed host.** `src/lib/webinar/env.ts` and
   `src/app/conversation/join/route.ts`: https only, no credentials, host exactly `zoom.us` or a dot-suffixed
   subdomain; try `https://zoom.us.evil.example/`, `https://evil.example/?zoom.us`, `https://zoom.us@evil.example/`,
   `//zoom.us`, mixed case and a trailing dot. The replay URL is deliberately any https host without
   credentials: confirm it is only ever rendered as a link's `href`, never used as a redirect target, and that
   a `javascript:` or `data:` value cannot pass. No branch may produce an open redirect or a 5xx.
14. **The payment grant cannot be affected.** In `grantFromSession`: the new call sits after the entitlement
   write, returns before fetching on a null email or unset env, has a timeout, catches everything, and cannot
   change the return value. `tagPremiumMember` and its `if` are byte-identical to the merge base. No member
   upsert was added. `tests/e2e/integrations/webhook-fulfilment.spec.ts` is unchanged and still passes.
15. **`next.config.ts` still emits the same headers.** The `headers()` body and CSP array are byte-identical;
   the build-phase assertion runs only for `PHASE_PRODUCTION_BUILD`, treats unset as valid, and names a
   variable without printing its value. Confirm nothing in the function form can throw at runtime.
16. **Dormant means unreachable.** With no `WEBINAR_STARTS_AT`: every `/conversation` route is 404 — including
   `/conversation/join` while `WEBINAR_ZOOM_URL` is set, which is the Production state — and the API refuses
   before any Mailchimp call. With a start in the past the forms are closed server-side, not only hidden in
   the UI. Confirm /conversation, /conversation/replay and the three handlers are rendered per request (ƒ in
   the build output), so the state follows the clock and not the build.
17. **No secret-type value is rendered.** The Zoom URL appears in no HTML, JSON, log, calendar file or test
   attachment; the join spec uses `maxRedirects: 0` and never prints the `location` header. No `WEBINAR_*` or
   Mailchimp value has a public prefix or reaches client code.
18. **The script cannot send mail or touch real contacts.** `scripts/webinar-funnel.mjs`: campaign create is
    allowed for the seven named, unscheduled, empty drafts only; no call that SETS campaign content, sends,
    test-sends or schedules (the single `GET /campaigns/{id}/content` is read-only, is the only content
    route, and is what lets check and launch-check find a leftover "[" or a wrong link in a body); the `premium` tag is only looked up or created empty; `cleanup` archives only members matching both
    the plus-tag pattern and a conv1 tag, and never calls delete-permanent; `selftest` uses `is_syncing: true`
    and archives in a `finally`; nothing prints the key, the list id or a full address.
19. **The workflow exposes secrets no wider than needed.** `.github/workflows/webinar-funnel.yml`: least
