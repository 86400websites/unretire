Deep pass for this sprint (it adds the site's first shared-password page, a public write route, a call inside
the live sign-up route, a migration with two functions, and two server-only values):

9. The report gate. Nothing reads the new tables before the session check passes, on the page and on
   /report/save. The report is off — no form, no number — when either REPORT_* value is missing or too short.
   The password comparison is constant-time on equal-length digests. The cookie is HttpOnly, Secure,
   SameSite=Lax, Path=/report, and its value changes when either REPORT_* value changes. The password never
   reaches a log, a redirect URL or a response. The login limiter fails closed. The page is noindex and absent
   from src/app/sitemap.ts.
10. /report/save. A cross-site POST cannot write: the session, an Origin whose host passes the existing
    isAllowedHost (src/lib/auth/safe-origin.ts — not a second implementation), the rate limit and validation all
    precede the write, and every refusal writes nothing. Dates and numbers outside the stated ranges are refused.
    Every redirect from /report/login and /report/save uses a relative Location, never an address built from
    request headers (Known issue 42).
11. POST /api/conversation/arrival. Dormant and closed are decided before any work; a bot user agent stores
    nothing; the limiter fails closed in its own bucket; only the eight keys are accepted; no part of the body
    is echoed; nothing identifying is stored in the new tables (the shared limiter's short-lived scrambled IP
    is the existing rate_limits row, which privacy §14 (f) discloses).
12. POST /api/conversation. For every input and upstream answer the status and body equal master's; the record
    call sits only before the two accepted returns and can neither throw nor alter the response; a test address
    records nothing; the email address never leaves the server in a database request.
13. The person code is a keyed HMAC of the trimmed, lower-cased address; nothing in the repo or the database
    can turn it back into an address without the server-only secret.
14. Migration 0005. RLS on with no policy on all three tables; both functions SECURITY INVOKER, search_path
    pinned, execute held by service_role only; record_campaign_person keeps the first source and sets
    registered_at once in one statement; campaign_report aggregates in the database, keeps sources that have
    visits only or registrations only, and starts at 00:00 Africa/Johannesburg on count_from; the down file
    reverses the schema only.
15. The numbers. resolveSource follows the record's rules in order (plus Meta's short names fb and ig — the
    record's build notes), with whole-label host matching; a visit is
    counted once per tab and never when navigator.webdriver is true or before prerender activation; no number
    is computed from rows fetched into JavaScript (the API's row cap would truncate it).
16. Env boundary. REPORT_PASSWORD and REPORT_SECRET appear in no client component and no NEXT_PUBLIC_ name;
    `grep -rl "REPORT_SECRET\|REPORT_PASSWORD" .next/static` after a build prints nothing; .env.example holds
    placeholders only.
17. The privacy page. Each new sentence matches the code it describes (and, for Vercel Web Analytics, the
    vendor page the copy file cites) and is the owner-approved wording verbatim.
18. Tests. No spec sends a valid POST to /api/conversation or a valid arrival outside the Preview and a local
    server; the allowed path of the report spec ran on the Preview at HEAD_SHA; specs restore process.env and
    fetch; the existing conversation-route assertions are unchanged.
19. The bypass secret in test output. Every request method of the shared `api` fixture goes through
    withQuietErrors (tests/e2e/fixtures.ts, added to the allowed files by D-64), and the S6.2 specs also use
    guarded() (tests/e2e/webinar/request-guard.ts), so a failed request's error — which Playwright fills with
    the request's headers, the deployment's bypass header among them — never reaches error-context.md, which
    the workflow uploads (Known issue 69); tests/e2e/webinar/request-headers.spec.ts proves both the leak and
    the fix. No S6.2 spec records a trace, and no step title or assertion message carries the
    test password or the session.
20. The build notes in the sprint record's status block. Each decision taken during the build is as described
    and safe: a sign-up is counted whenever REPORT_SECRET is usable, even while the page is off; a report box
    that is missing or not text is refused, never read as empty; the password error is role="alert"; every
    longer time limit (`grep -rn "test.setTimeout" tests/e2e/webinar tests/e2e/abuse/public-write-endpoints.spec.ts`)
    states its reason; the report's two limiter windows are 600 s, at most ten times the shortest window of
