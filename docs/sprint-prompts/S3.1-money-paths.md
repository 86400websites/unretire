## Outcome

**Complete on the branch.** `claude/s3.1-money-paths`, code at `15697d9`.

### What was wrong, and what it cost

The five issues were **one failure story**, which is why they were fixed together:

1. A customer pays. Stripe calls the webhook.
2. **#22** — the entitlement write fails. `supabase-js` v2 returns `{data, error}` and does **not** throw, so the discarded result looked identical to success, and the handler answered `200`. Stripe recorded delivery and **never retried**.
3. **#45** — the customer lands on `/account?checkout=success`, and the banner rendered from that query string alone: *"Payment successful. Welcome — your access is ready below."* No entitlement check.
4. The customer has paid, has nothing, and has been **reassured**. Nobody finds out.

Separately, **#2** meant that landing page was `/unretire/account` — a 404 left by the promote-to-root refactor — so the journey broke even when the payment worked; **#1** meant every Premium book download returned 500 + JSON because the master PDFs were read from an orphaned path; and **#40** left session creation without an idempotency key.

### The fixes

| # | Change | Evidence |
|---|---|---|
| **22** | Both the upsert and the cancellation update capture `{error}` and return **500 so Stripe retries**. A 200 now means the entitlement really changed. Satisfies **I4**. | `webhook/route.ts` |
| | Events whose metadata names no user are **logged and acknowledged**, not retried — the live Stripe account is shared (#41) and a 500 would make Stripe redeliver a foreign event for days. | |
| **45** | The banner follows the entitlement read, not the URL. A just-paid customer whose webhook has not landed gets an honest pending message rather than silence. | `account/page.tsx` |
| **1** | `MASTERS` resolves `src/app/account/_book/…`. | `book-download/route.ts` |
| **2** | Three destinations repointed: `success_url` → `/account?checkout=success`; already-owned → `/learn/course`; reset link → `next=/reset-password`. | Verified locally: each new path resolves (200/307), each old `/unretire/*` returns **404** |
| **40** | `idempotencyKey` scoped to buyer+product, bucketed to the minute — a double-click replays the original session, a genuine later attempt gets a fresh one. | `lib/stripe/checkout.ts` |
