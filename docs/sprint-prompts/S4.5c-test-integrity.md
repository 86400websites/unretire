# Sprint Record — S4.5c — Test Integrity

Branch `claude/s4.5-launch-floor`, **PR #24 — open, not merged.** Continues S4.5.

## Why this sprint exists

The pre-launch independent review returned **REQUEST CHANGES** with 8 Blocking and 2
Should-fix findings. Findings 1–9 were fixed in `231b637`. **Finding 10 — test gaps — was
left open**, and the reviewer marked it *"cannot be deferred past S5.1b"*:

> `/privacy` and `/terms` omitted from `PUBLIC_ROUTES`; the social-image assertion is
> conditional and passes when the tag is missing; several claimed closures have no
> red→green spec.

That is the whole of S4.5c's brief. The two named spec defects are trivial; the third
clause is not, and auditing it turned up more than the reviewer had room to enumerate.

## What the audit found

Every fix in the S4.5 range was mapped to the spec that proves it. Of the nine review
findings, **exactly one — F9, the exact-host origin trust — had a spec that would go red
against the pre-fix code.** The other eight had none. Nor did the security headers
(issue 46), the legal pages (issue 3), the lesson count (issue 8) or the placeholder
removals (issue 9) — all closed on the strength of a manual read.

Three of the gaps were hiding live defects.

**The webhook proofs needed a decision.** Every branch of Findings 1–4 sits behind
`constructEvent`, and the runner holds no Stripe signing secret, so an HTTP spec can only
ever see the 400 — which is exactly what the existing webhook spec asserted, and exactly
why it would have passed against the money-losing code. `grantFromSession` and
`syncSubscription` are therefore exported and asserted directly against their real inputs
with a recording stub in place of the admin client, the same pattern `safe-redirect.ts`
and `safe-origin.ts` already use. The stub also proves the thing a status code cannot:
that a refused event performs **no write at all**.

### 3. Live defects the missing tests were hiding

1. **Known issue 44 was never fixed.** `/api/subscribe` still logged the whole Mailchimp
   response and returned its `detail` string to anonymous callers. It was S4.5 scope
   (`ROADMAP.md:77`), the tracker still said `Open — S4.5`, and `validation.spec.ts` still
   said FM-009 *"belongs to the S4.5 fix sprint"*. Fixed: a fixed message to the caller,
   the status code only in the log. The catch-all no longer logs the error's own message
   either — a thrown `fetch` error carries the request URL, which contains the audience id.
2. **Known issue 9 was closed on two pages out of three.** `/stories` was still telling
   every visitor, in the page's own words, *"Placeholders below — swap in real, named
   stories as they're gathered."* PG-007 names `/book`, `/stories` **and** `/community`.
   Removed on the same basis and equally reversible.
3. **The parity checkout helper could no longer complete a purchase.** S3.1 changed the
   `success_url` to `/account?checkout=success`; `helpers/parity.ts` still waited for the
   pre-S3.1 `/unretire/account`, so the wait could only ever time out. Fixed.

### 4. The suite's own integrity

The reviewer counted five tests in this range that passed or failed for incidental
reasons. These are the ones still standing:

- **Both paid-checkout parity specs had stopped buying anything.** Once the fixture owns
  the product the spec asserted the entitled state and returned — so *"a purchase reaches
  Stripe sandbox and grants access"* reported PASS without a purchase, on every run since
  S2.5. That is also **why nobody noticed defect 3 above**: the code path that would have
  failed was no longer being run. Two defects, hiding each other, in the primary
  conversion. The early return now fails with instructions unless
  `E2E_ALLOW_ALREADY_OWNED=1` says the reduced proof is wanted.
- **AC-012's bundle scan skipped chunks it could not fetch.** `if (res.status() !== 200)
  continue` — so before S5.1a's bypass fix, every chunk would have 401'd and the scan
  would have declared the paid course safe having read nothing. Unreadable chunks are now
  a failure, and the count of chunks actually read is asserted.
- **IN-005 counted `button:not([disabled])` over the whole page**, which matches the site's
  own header chrome, so it could never reach zero on any page. Scoped, and inverted to the
  assertion that matters: an entitled member has **no** locked rows.
- **A run with no fixture password silently dropped every access-boundary, paid-content,
  money-path and logout spec** and reported green. `playwright.config.ts` now refuses to
  run a partial suite in CI.
- **`origin-guard.spec.ts` cleared two of the four env vars it sets**, so a value from one
  test stayed visible to the next.

## Two things this sprint got wrong

1. **PG-002 was written as one test crawling ten pages, then split into ten, then merged
   back into one.** The split was the wrong instinct applied from the right precedent: the
   26-route sweep in `public-pages.spec.ts` was correctly split because each route is
   independent, but these ten pages *share* a header and a footer, so per-page checking
   turned ~50 distinct routes into ~250 requests and made it worse. It is one deduped
   crawl with a documented budget, in a folder only one profile runs.
2. **Three form specs failed on the first run and the app was fine.** They navigated with
   `waitUntil: "domcontentloaded"` and clicked before React had hydrated, so the browser
   performed the form's native submission and no POST was ever issued. Diagnosed by
   probing rather than by guessing, which is the only reason it was not "fixed" by
   loosening the assertion.
