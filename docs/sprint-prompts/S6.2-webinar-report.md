## Goal
A private page, /report, that shows the owner three numbers and one table for the current webinar campaign —
visits to the sign-up page, people registered, people who showed up, and where visitors and registrants came
from — plus the fixed set of tracking links his team posts, an owner's guide, and a privacy page that says
what the site really does.

1. On the Preview, /report without the password shows the password form and no number. With the Preview test

   saving the boxes changes the page. A wrong password and a save from another site are refused.

   once under LinkedIn, a reload in the same tab is not counted again, and the registration POST from that tab
   carries `linkedin`. A person whose first accepted sign-up came from one link keeps that link's row when they
   register later from an untagged link.
3. A +ur-test- or +ur-e2e- address is never counted. No table this sprint adds holds an email address, a name,
   an IP address, a user agent, a referrer or a URL.
4. For every input and every upstream answer, POST /api/conversation responds exactly as master does: the
   counting can never fail, change or block a sign-up.
5. The privacy page describes the counting, Vercel Web Analytics, the Premium list addition and the older
   /webinar page's extra fields, in words the owner approved; Known issue 63 is closed.
6. docs/WEBINAR-FUNNEL.md section 10 lets the owner open the report, set "Counting from", give his team the
   links, set up an ad with the right link and type in the Zoom number, without help.
7. Migration 0005 is applied to unretire-test by the builder and to unretire-prod by the owner by hand, and
