### A harness defect found after the verdict, and fixed (Known issue 56)

A **docs-only** commit went red — PY-003 and PY-004, both needing the signed-in fixture's
session. A documentation change cannot break the site, so it was chased rather than re-run.

Two runs had overlapped: 33501412653 (`3ddc78a`, 11:13:58–11:16:55) and 33501489016
(`84372f0`, 11:14:51–11:18:00). `AC-002`'s `signOut()` is global-scope, so the first run
revoked the second run's fixture session and `/account` bounced to `/login`.

**It is the same defect S5.1a fixed, one level out.** That fix keyed the concurrency group on
the commit SHA — which serialises the two triggers of *one* commit and does nothing about two
commits pushed a minute apart. The key named the run; the resource needing protection is the
single set of fixture accounts. Fixed in `b7af693` with one static group, so every run queues.

Proven at `b7af693`: the `deployment_status` run sat `pending` until the `pull_request` run
finished, then both returned **214 passed**.

**The verdict is unaffected**, and the check is mechanical rather than a matter of judgement:

```
git diff --name-only f8702f1..HEAD -- src/ tests/ playwright.config.ts package.json
```

returns nothing — everything after the certified head is documentation plus that one CI key.
