### How to resume in a fresh AI session

1. Read this file, then the active sprint's scope + exit gate in `docs/ROADMAP.md`.
2. Read the agent-instructions file (`CLAUDE.md` / `AGENTS.md`) and the docs it points to for the task.
3. Verify the repo state yourself (package manifest, source tree, `git log`). If it disagrees with this file, report the mismatch; update this file only when the task authorizes it.
4. Work only inside the active sprint. Anything else → propose it under Open decisions or the backlog.
5. Before ending: update §1–§3 here, tick the roadmap checkboxes, and include this file in the PR.

Why this matters: this ritual makes the project session-stateless — anyone can cold-start and resume mid-sprint with zero verbal briefing.

### Launch-blocking set

The single list of issues that **must be closed before this site takes real money from a real customer or is
publicly launched.** Everything else in §10 is scheduled work; these are the gate. If any line below is still
open, the answer to *"can we launch?"* is **no** — regardless of how green the test suite is.

**Money must actually reach the customer**

- **22** — the Stripe webhook returns HTTP 200 after a failed entitlement write, so Stripe never retries: the customer pays and silently gets nothing. *(S3.1)*
- **45** — `/account?checkout=success` shows "Payment successful… your access is ready" from the query string alone, so issue 22 fails **invisibly** — the customer is reassured while receiving nothing. *(S3.1)*
- **40** — no Stripe idempotency key on session creation, so a double-click or retry can charge the same customer twice. *(S4.3)*
- **39** — no invoice/subscription lifecycle handling, so a failed Premium renewal leaves access `active` and Premium is given away. *Launch-blocking for **Premium** specifically; a course-only launch is not gated by it.* *(S4.3)*

**Paid product must not be free, and users must not be phishable**

- **37** — the whole course (all 48 lessons' video IDs and worksheet paths) ships in the client bundle and four worksheet PDFs sit in `public/`, so anonymous visitors can take the $99 product. *(S4.3, with a denied-case test in S5.1)*
- **38** — `?next=//evil.example` escapes the redirect guard in `src/app/auth/confirm/route.ts:19-21`, turning the auth-email landing route into an open redirect. *(S4.4)*

**The already-known breakage that reaches paying users**

- **1** — `/api/book-download` reads master PDFs from stale `src/app/unretire/account/_book/...` paths, so premium downloads always fail. *(S3.1)*
- **2** — the three stale `/unretire/*` destinations (Stripe `success_url`, already-owned redirect, password-reset `next`) all 404 on the customer's most important journeys. *(S3.1)*
  - *(1 and 2 together are what the Codex review filed as its stale-path finding — they are the repo's equivalents of that single finding. Do **not** read this as Known issue 11, which is unrelated `package.json` hygiene and is **not** launch-blocking.)*

**Legal and infrastructure floor**

- **5** — public write endpoints have no rate limit or bot check; launch-blocking by `docs/SECURITY-CHECKLIST.md` §5. *(S4.5)*
- **3** — `/privacy` and `/terms` 404, and you cannot lawfully take payment without them. *(S4.5, owner supplies copy)*
- **27** — `unretireproject.com` DNS still points at a GoDaddy parking page, so the launch domain does not serve the site. *(S5.2, owner action at the registrar)*
- **46** — no security headers are configured (`next.config.ts:3-5`) and the live response carries HSTS only; `docs/SECURITY-CHECKLIST.md` §6 makes deployed-header verification a 🔴 blocking item, so launch cannot pass the security gate without them. *(S4.5 — added 2026-08-26, stage-gate Round 3 Finding 2)*
